# ЛидоКабан — парсер лидов с Google Maps

Личный инструмент лидогенерации (см. `docs/PRD.md`). Скрапит Google Maps по запросу
«город + категория бизнеса», собирает название/телефон/адрес/сайт/рейтинг, сохраняет
в CSV. Есть два интерфейса: консольный и десктопное GUI-приложение (pywebview),
упаковано в `.app` через py2app. Тема оформления — кабан (🐗), это осознанный выбор
пользователя, не убирать при рефакторинге.

## Структура

- `config.py` — константы (MAX_LEADS=100, паузы, пути к CSV/JSON, FOLLOWUP_DAYS)
- `scraper.py` — Playwright-скрапинг Google Maps (генератор `run()`)
- `phone.py` — нормализация телефона в E.164 через `phonenumbers`
- `enrich.py` — контакты с сайта бизнеса (Telegram/WhatsApp), проверка «это бот» через t.me, ссылка Zalo для VN
- `sources.py` / `scraper_2gis.py` — выбор источника; 2ГИС парсится перехватом JSON страницы выдачи (нужен RU IP, с VN — капча). Написан без доступа к живому сайту, см. раздел про 2ГИС ниже
- `storage.py` — запись лидов в CSV + история запусков в `runs.json`
- `outreach.py` / `templates.py` — полуавтомат рассылки в Telegram (см. `docs/OUTREACH.md`)
- `main.py` — консольная версия (input() на город/категорию/страну)
- `app.py` — GUI-версия: класс `Api`, дергает pywebview, тот же scraper/storage
- `ui.html` — фронтенд GUI (ванильный JS, без фреймворков), кабанья тема
- `assets/icon.icns` — иконка приложения (кабан-эмодзи на градиенте)
- `setup.py` — конфиг py2app для сборки `.app`

## Важные технические грабли (уже наступили, не наступать снова)

- **Селекторы Google Maps нестабильны.** `#searchboxinput` для поля поиска Google
  убрал — используй `input[name="q"]`. Для телефона/адреса НЕ парси текст кнопки
  через CSS-класс (`inner_text()` по классу) — классы у Google минифицированы и
  переиспользуются между разными элементами (в т.ч. иконками с невидимыми
  private-use глиф-символами вроде ``), результат нестабилен. Вместо этого
  парси атрибут `aria-label` кнопки (`"Phone: +84 934 773 134"`,
  `"Address: ..."`) — он чистый и стабильный.
- **Рейтинг/отзывы** берутся из `div.F7nice` через `inner_text()` целиком
  (`"4.7\n(2,196)"`, парсится по строкам) — НЕ через `aria-label` отдельных
  спанов, там периодически null/timeout.
- **headless=False зависает в песочнице агента** (Bash-тул Claude Code без
  реального дисплея) — используй `headless=True` для любого автотестирования
  скрапера отсюда. В обычном Terminal пользователя `headless=False` работает
  нормально и специально оставлен, чтобы видеть браузер вживую.
- **py2app + playwright конфликт**: если в `setup.py` в `options.packages`
  указать `"playwright"` целиком, сборка падает на
  `ImportError: No module named playwright._impl.__pyinstaller...` — это
  служебный хук для PyInstaller, которого нет как обычного модуля. НЕ добавляй
  playwright в `packages`, он и так подхватывается через обычный import graph.
  Сейчас `excludes: ["playwright._impl.__pyinstaller"]` подстраховкой.
- **playwright и greenlet в `.app` должны лежать обычными папками, не в zip.**
  py2app пакует их в `lib/python314.zip`, откуда не запускается `driver/node` и
  не грузится `greenlet/_greenlet.so` → скрапинг падает мгновенно, в GUI «0 лидов»,
  в runs.json статус `error`. После сборки запускай `./postbuild.sh` (копирует
  папки в `dist/...` и обновляет `/Applications`). Chromium ищется через
  `PLAYWRIGHT_BROWSERS_PATH` (выставлен в начале `app.py` на
  `~/Library/Caches/ms-playwright`). Ошибки скрапинга в `.app` пишутся в
  `~/leadokaban_error.log`.
- **Сборка `.app` занимает ~13 минут** (анализ графа модулей pyobjc/webview),
  это нормально, не значит, что зависло — проверяй `ps aux | grep py2app` на
  активность CPU, а не просто наличие процесса.
- **После каждой пересборки `.app` нужно вручную обновить копию в
  `/Applications`** — сборка кладёт новый файл в `dist/`, но не трогает то, что
  уже скопировано в `/Applications`. Команда:
  `rm -rf "/Applications/Парсер лидов.app" && cp -R "dist/Парсер лидов.app" /Applications/`
  Делай это автоматически после каждой пересборки, не дожидаясь просьбы.

## 2ГИС

`scraper_2gis.py`. Проверено на живом сайте только частично (первый запуск с RU VPN:
Ивантеевка, страница открылась, слаг `ivanteevka` подошёл, в списке 5 фирм).
Что выяснилось: **телефонов в списке выдачи нет**, они только в карточке за кнопкой
«Показать телефон». Запросов `/items` в сетевом журнале не видно, перехват JSON
оказался угадыванием схемы и в одиночку не работает.

Поэтому парсер опирается на устойчивое: ссылки `a[href*="/firm/<id>"]` в списке,
текст блока рядом (название/адрес/рейтинг), затем отдельная загрузка карточки
`/firm/<id>`, клик по тексту «Показать телефон» и чтение ссылок `tel:`.
Сайт/Telegram/WhatsApp — из ссылок карточки. JSON-ответы и ld+json разбираются
как дополнительный источник. Пагинация `/search/<запрос>/page/N`, домен по коду
страны (KZ → 2gis.kz), город → слаг (`CITY_SLUGS`, либо латиницей вписать слаг из
адресной строки). Telegram/WhatsApp из карточки подмешиваются в `enrich.build_row`.
Одна карточка = одна загрузка страницы плюс пауза, сотня лидов около 15 минут.

**Неизвестный слаг 2ГИС не отвергает, а молча показывает другой город** (по RU IP это
Москва; на самом деле сначала 404). Слаги угадывать нельзя: у Сергиева Посада это
`sergiev-posad`, у Ростова `rostov-on-don`, у Н. Новгорода `n_novgorod`. В любой странице
2ГИС зашит каталог ~1200 городов (`"name":"…","country_code":"ru","alias":"…"`),
`_resolve_city` берёт слаг оттуда (`_catalog_alias`); `CITY_SLUGS` и транслитерация
остались запасным путём. Результат всё равно проверяется: адрес страницы и название
города в адресах фирм. Не нашёл, падает с просьбой вписать слаг латиницей в поле «Город».
2ГИС ищет по всей карточке фирмы, поэтому в выдачу попадают ветклиники и зоомагазины
с услугой «груминг». Против этого поле «Тип заведения содержит» (`type_filter`):
слова через запятую ищутся в названии и типе фирмы из списка, лишние карточки даже
не открываются.

Что НЕ проверено на живом сайте: работает ли клик «Показать телефон» и отдаёт ли он
`tel:`-ссылки, формат рейтинга и пагинация `/page/N`. Каждый запуск пишет в
`~/Documents/ЛидоКабан/debug_2gis/last_run/` HTML списка и первой карточки, ссылки
карточки (`card_anchors.json`), результат (`card_result.json`) и сетевой журнал без
тайлов. Если поля пустые, смотри туда и правь по факту.
Капча в окне браузера решается руками, скрапер ждёт до 3 минут.
Для автотеста задавай `LEADOKABAN_HEADLESS=1`, но с не-RU IP сайт отдаёт капчу.

## История запросов

Каждый запуск (и `main.py`, и `app.py`) получает `run_id` (таймстемп), пишется в
`runs.json` (город/категория/страна/дата/найдено/пропущено/статус) через
`storage.add_run` / `storage.update_run`. Каждая строка в `leads.csv` тоже несёт
`run_id`, чтобы можно было выбрать лиды конкретного прошлого запуска
(`storage.get_leads_for_run`). В GUI это вкладка «📜 Прошлые вылазки».

## Данные — не в git

Файлы `leads.csv` и `runs.json` лежат в `~/Documents/ЛидоКабан/` (`config.DATA_DIR`), а не
рядом с кодом: раньше они были относительными и жили внутри `.app`, поэтому
`postbuild.sh`/переустановка (`rm -rf` приложения) стирала всю историю.

`leads.csv`, `runs.json`, `build/`, `dist/`, `.env` — в `.gitignore`, это
локальные данные/артефакты сборки, не коммитить.

## Полуавтомат рассылки

Вкладка «📨 Рассылка»: конвейер по одному лиду, текст КП в буфер + открытие
чата через `tg://`, отправляет пользователь руками. **Автоотправку не делать
никогда** — userbot (Telethon/Pyrogram) на холодной рассылке ловит бан номера и
уносит с собой переписку с теми, кто уже ответил. Подставить текст в поле ввода
Telegram схемой `tg://` нельзя, поэтому и нужен буфер обмена.

Статусы лидов — в `outreach.json`, шаблоны — в `templates.json`, оба в
`DATA_DIR`. Шаблоны в файле, а не в коде, чтобы правки пользователя переживали
пересборку `.app`. Подробности и принятые решения — `docs/OUTREACH.md`.

## Что сознательно не делаем (см. PRD)

- Оценку релевантности лида (нужна ли бизнесу автоматизация) через AI/скоринг —
  пользователь сам смотрит на `has_website`/`rating`/`reviews_count` в CSV и
  решает руками. Не предлагать LLM-скоринг лидов без явного запроса.
- Официальный Google Places API — только скрапинг с паузами.
- Дедупликация лидов между запусками.

## Тестирование изменений

Т.к. агент работает в песочнице без реального дисплея, GUI (`app.py`,
собранный `.app`) сам запустить и увидеть не может — только: `py_compile` на
синтаксис, `headless=True` тест самого `scraper.py`/`main.py` для проверки
данных, и просьба к пользователю запустить `.app` и описать, что видно.
