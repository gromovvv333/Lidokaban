# PRD: Парсер контактов бизнесов с Google Maps

**Автор:** пользователь (обучение кодингу, лидогенерация для продажи автоматизаций малому бизнесу)
**Дата:** 2026-09-10
**Статус:** MVP — черновик

---

## 1. Контекст и Big Job

Пользователь учится программированию и планирует продавать малому бизнесу мини-продукты автоматизации (например, ботов для записи клиентов). Прежде чем что-то продать, нужно **найти, кому продавать**. Ручной поиск лидов — это ресурс, которого нет: время нужно тратить на создание и продажу самих автоматизаций, а не на ручной перебор Google Maps.

**Big Job (верхнеуровневая цель):** быстрее выйти на первые продажи автоматизаций малому бизнесу, минимизировав время, уходящее на поиск потенциальных клиентов.

Побочная цель пользователя — получить практический опыт разработки в процессе создания этого инструмента.

**Важно:** сам парсер — это не продукт на продажу. Это внутренний инструмент лидогенерации для пользователя, который потом вручную связывается с лидами через WhatsApp или почту.

---

## 2. Сегменты и Jobs-to-be-Done

Точный приоритетный сегмент ещё не определён — решение будет приниматься по факту первых продаж. На старте рассматриваются три сегмента малого бизнеса:

| Сегмент | Jobs-to-be-Done |
|---|---|
| **Локальный сервисный бизнес** (барбершопы, салоны красоты, автосервисы, стоматологии) | Хотят, чтобы клиенты сами записывались онлайн, не отвлекая администратора от звонков; не терять клиентов, звонящих в нерабочее время |
| **Общепит** (кафе, small-restaurants, кофейни) | Хотят автоматически принимать/подтверждать бронирования столиков; собирать отзывы/лояльность без найма отдельного человека |
| **B2B услуги / мастера-фрилансеры** (репетиторы, мастера маникюра, частные специалисты) | Хотят выглядеть солидно и автоматизировать запись как у крупных компаний; меньше времени тратить на переписку по одним и тем же вопросам |

Приоритизация сегментов по итогам первых пилотных запусков и продаж выносится за рамки MVP.

## 3. Рискованные предположения

| # | Гипотеза | Валидируется в MVP? |
|---|---|---|
| 1 | Google Maps содержит актуальные и рабочие контакты (телефон/WhatsApp) для нужных категорий бизнеса и регионов | ✅ Да |
| 2 | Владельцы малого бизнеса откликаются на холодные сообщения в WhatsApp/почту от незнакомого человека | ✅ Да |
| 3 | Технически возможно парсить Google Maps без критичных блокировок при разумном объёме запросов | ✅ Да |
| 4 | Спарсенные лиды релевантны (у бизнеса реально есть боль, которую можно закрыть автоматизацией) | ⛔ Не в MVP — гипотеза для будущих версий |
| 5 | Одного контакта (телефон/WhatsApp) достаточно для первого касания, email не обязателен | ✅ Да |

## 4. MVP: пользовательский флоу

1. Пользователь запускает парсер с параметрами: **город/регион + категория бизнеса** (например, "рестораны, Дананг").
2. Парсер ищет соответствующие места в Google Maps методом скрапинга (без Places API).
3. Между запросами парсер делает паузы, имитируя обычного пользователя, чтобы снизить риск блокировки.
4. По каждому найденному месту собирает: **название, телефон, адрес**.
5. Номер телефона автоматически приводится к международному формату (код страны + очистка от лишних символов) через простую правило-ориентированную логику (regex), без использования LLM.
6. Лиды без телефона исключаются из выдачи.
7. За один запуск собирается **до 25 лидов**. Если найдено меньше — отдаются все найденные, с уведомлением пользователю, что на этом релевантные результаты в этом регионе/категории закончились.
8. Результат сохраняется в **CSV-файл** (кроссплатформенный формат, открывается в Numbers на Mac, Excel или Google Sheets).
9. Если во время запуска происходит сбой (обрыв сети, блокировка от Google и т.п.) — все лиды, найденные **до момента сбоя**, сохраняются в файл, а не теряются.
10. Время выполнения не критично — 10+ минут на запуск приемлемо.

### Формат результата (CSV)

| Название | Телефон (междунар. формат) | Адрес |
|---|---|---|

*Поле "почему лид релевантен" — не в MVP, добавляется в следующих версиях (см. Roadmap).*

## 5. Out of Scope (сознательно не делаем в MVP)

- ❌ Автоматическая отправка сообщений лидам (WhatsApp/email). Есть полуавтомат в Telegram: приложение готовит текст и открывает чат, отправляет человек (`docs/OUTREACH.md`).
- ❌ Источники, кроме Google Maps (Instagram, Yelp и т.п.) — только на будущее.
- ❌ Официальный Google Places API — используем скрапинг с паузами; переход на API — будущая доработка при необходимости.
- ❌ Дедупликация лидов между разными запусками — не критично для MVP, но фиксируется в бэклоге.
- ❌ Автоматическая оценка релевантности лида (например, "нет сайта" / "мало отзывов") — как и гипотеза №4, откладывается.
- ❌ UI/дашборд — взаимодействие через запуск скрипта с параметрами, результат — CSV-файл.
- ❌ Google Sheets интеграция — на старте локальный CSV-файл.

## 6. Edge cases и принятые решения

| Edge case | Решение |
|---|---|
| Найдено меньше 25 лидов по заданным параметрам | Отдать все найденные, уведомить пользователя, что на этом релевантные результаты закончились |
| У бизнеса нет номера телефона | Исключить лид из выдачи |
| Номер в локальном формате, не пригоден для WhatsApp | Автоматически привести к международному формату по коду страны региона поиска (regex, без LLM) |
| Один и тот же бизнес встречается в разных запусках | Не обрабатывается в MVP; занесено в бэклог на будущее (дедупликация) |
| Риск блокировки от Google при частых запросах | Скрапинг с паузами между запросами (не Places API); пользователь готов мириться с редкими сбоями/паузами |
| Формат выходного файла на macOS | CSV — открывается в Numbers, Excel, Google Sheets без доп. ПО |
| Сбой в процессе парсинга (обрыв сети, блокировка) | Сохранять частичный результат — все лиды, найденные до сбоя, а не терять всё |

## 7. Метрики успеха MVP

Косвенные, так как продукт внутренний:
- Успешный запуск с параметрами "город + категория" стабильно возвращает лиды с валидными телефонами.
- Время от запуска до готового CSV-файла ≤ 15 минут при обычной нагрузке.
- Доля лидов с телефоном в международном WhatsApp-формате — 100% (все включённые в выдачу).
- Пользователь может использовать полученные лиды для реальной рассылки без ручной донастройки данных.

## 8. Roadmap (после MVP)

- Оценка релевантности лида (валидация гипотезы №4): признаки типа "нет сайта", "мало отзывов", "давно не обновлялся профиль".
- Дедупликация лидов между запусками.
- Переход со скрапинга на официальный Google Places API при масштабировании.
- Дополнительные источники данных (Instagram, Yelp и т.п.).
- Экспорт напрямую в Google Sheets вместо/в дополнение к CSV.
- Возможная автоматизация первого касания (с осторожностью — риск спама/блокировки WhatsApp-номера).
